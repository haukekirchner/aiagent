## Rules from ai-service-manager

These are defined once, in `~/projects/ai-service-manager/rules/`, and apply here.
Read the file before working on anything it covers — this list is only a pointer,
and the reasoning that makes a rule worth following lives in the rule.

- **shared agent policies and compatibility review** — `~/projects/ai-service-manager/rules/agent-policy-sync.md`
  Agents in enrolled projects follow ASM's product-development, coding and communication policies. Keep generated rule pointers and policy checks synchronized. Claude Code, OpenCode and Codex are…
- **maintain changelogs and release notes** — `~/projects/ai-service-manager/rules/changelog.md`
  Describe changes to user-visible behavior in the project's changelog in the same commit as the change. Write release notes when preparing a release.
- **tooling runs in containers** — `~/projects/ai-service-manager/rules/containers.md`
  Tools, builds, renderers, test runners and checks run in throwaway containers started by a script in the repository, not from software installed on the host. The containers run on the Raspberry Pi…
- **counterparts are not synced, an issue is suggested** — `~/projects/ai-service-manager/rules/counterparts.md`
  A mechanism two apps share is changed in one app at a time: the change is not carried into the other app as a side effect, an issue for the other app is suggested instead, and the branch says…
- **one design system across the apps** — `~/projects/ai-service-manager/rules/design-system.md`
  Copy the tokens, follow the structure, and differ only where you can say why.
- **commit and push significant changes** — `~/projects/ai-service-manager/rules/git-hygiene.md`
  When a change is significant, commit it with a human-readable message and push. Do not leave significant work uncommitted, and do not leave commits sitting unpushed.
- **check security before code leaves the machine** — `~/projects/ai-service-manager/rules/security-checks.md`
  No secret is committed, and no change is pushed with a known high-severity problem in what it touches: a vulnerable dependency, a misconfigured Dockerfile, a broken shell script. ASM's hooks check…
- **every service stands on its own** — `~/projects/ai-service-manager/rules/shared-services.md`
  A service is owned by exactly one project. Everything else is a consumer, and a consumer configures itself — it never deploys, backs up, or reconfigures what it uses.

A project may differ from a rule where it can say why, in a comment next to the
code that differs. An undeclared difference is a mistake; a declared one is a
decision. Do not edit this section — it is generated by
`ai-service-manager/scripts/sync-rules.py`.

## ASM project workflow

This project is enrolled in ai-service-manager. Use the agent-hub skills for setup
and run reporting. Register this session before committing; lifecycle hooks do
this automatically when installed and trusted. If a commit cannot identify your
run, use `asm run register --tool TOOL --session ID --model MODEL` and pass the
returned ID as `ASM_RUN_ID` to Git. Never guess token counts: ASM measures them
from its usage ledger. Run `asm project doctor` to check local policy wiring.
